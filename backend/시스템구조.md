## 서비스 개요

**SkinMate**는 사용자가 얼굴 사진을 업로드하면 AI가 피부질환(아토피, 건선, 지루, 주사, 여드름, 정상 총 6가지)을 분석하여 진단하고, 진단 결과에 맞는 올리브영 더마코스메틱 화장품 3개를 추천해주는 서비스입니다.

**추가 기능:**
- 좋아요 기능 (화장품 찜하기)
- 마이페이지 (분석 이력 조회)
- 화장품 검색 및 상세 정보 조회

## 전체 아키텍처

### 계층 구조 (Layered Architecture)

```
┌─────────────────────────────────────────┐
│   Router (API 엔드포인트)                │  ← HTTP 요청/응답 처리
├─────────────────────────────────────────┤
│   Service (비즈니스 로직)                │  ← 여러 Repository 조율, 복잡한 로직

│   Models (데이터베이스 테이블)           │  ← SQLAlchemy ORM 모델
```

## 핵심 기능별 데이터 흐름

### 1. 피부 분석 생성 (메인 기능)

#### 📍 엔드포인트
```
POST /api/skin-analysis
```

#### 요청
```
Content-Type: multipart/form-data

member_id: 1
image: [얼굴 사진 파일]
```

#### 전체 흐름

```
사용자 이미지 업로드
   ↓
1️⃣ SkinAnalysis 레코드 생성 (skin_analysis 테이블)
   ↓
2️⃣ 이미지 파일 저장 (로컬 디스크 + file 테이블)
   ↓
3️⃣ AI 피부 진단 (Vision 모델 → diagnosis 테이블)
   ↓
4️⃣ 화장품 추천 (현재: 더미데이터_recommendation 테이블 / 향후: RAG → recommendation 테이블)
   ↓
analysis_id 반환
```

#### 상세 단계

**1️⃣ 피부 분석 레코드 생성**

**파일 경로:**
- `router/analysis.py` → `services/analysis.py` → `repository/analysis.py`

**처리 내용:**
```python
# services/analysis.py
analysis = AnalysisRepository.create(db, {"member_id": member_id})
analysis_id = analysis.analysis_id
```

**DB 저장 (`skin_analysis` 테이블):**
```sql
INSERT INTO skin_analysis (member_id, created_at)
VALUES (1, NOW());
-- analysis_id: 123 (자동 생성)
```

**테이블 구조:**
```python
class SkinAnalysis:
    analysis_id = Column(Integer, primary_key=True, autoincrement=True)
    member_id = Column(Integer, nullable=True)
    created_at = Column(DateTime, default=datetime.now)
```

---

**2️⃣ 이미지 파일 저장**

**파일 경로:**
- `services/analysis.py` → `services/file.py` → `repository/file.py`

**처리 내용:**
```python
# services/file.py
FileService.upload_and_save(db, analysis_id, image_file)
```

**작업:**
1. 로컬 디스크에 파일 저장
   - 경로: `./uploads/{analysis_id}_{uuid}.jpg`
   - 예시: `./uploads/123_a3f5b891.jpg`

2. DB에 파일 메타데이터 저장

**DB 저장 (`file` 테이블):**
```sql
INSERT INTO file (entity_type, entity_id, file_path, file_name, mime_type, size)
VALUES ('skin_analysis', 123, './uploads/123_a3f5b891.jpg', 'face.jpg', 'image/jpeg', 245678);
-- entity_id = analysis_id
-- file_path (실제 파일 경로)
-- file_id (자동생성)
```

**테이블 구조:**
```python
class File:
    file_id = Column(Integer, primary_key=True)
    entity_type = Column(Enum(EntityType))  # 'skin_analysis' 또는 'cosmetic'
    entity_id = Column(Integer)             # analysis_id 또는 cosmetic_id
    file_path = Column(String(255))         # 실제 파일 저장 경로
    file_name = Column(String(255))         # 원본 파일명
    mime_type = Column(String(100))         # image/jpeg
    size = Column(Integer)                  # 바이트 단위
```

**다형성 연결 (Polymorphic Association):**
- `entity_type`과 `entity_id`를 조합하여 여러 테이블과 연결
- 예시:
  - `entity_type='skin_analysis', entity_id=123` → 사용자 얼굴 사진
  - `entity_type='cosmetic', entity_id=45` → 화장품 제품 이미지

**3️⃣ AI 피부 진단 (핵심 로직)**

**파일 경로:**

**처리 내용:**

**작업 흐름:**

1. **file 테이블에서 업로드한 이미지 조회**

```python
image_base64 = encode_image_base64(image)
```

3. **Vision 모델 호출 (LangChain + OpenAI Vision API) (RunPod 호스팅)**
--  프롬프트: core/prompt/diagnosis.yaml
--  6가지 질환 분류: 아토피, 건선, 지루, 주사, 여드름, 정상
```python
llm = ChatOpenAI(
    model=os.getenv("RUNPOD_MODEL_NAME"),
    api_key=os.getenv("RUNPOD_API_KEY"),
    base_url=os.getenv("RUNPOD_BASE_URL"),
    temperature=0.1,
)

messages = [
    HumanMessage(
        content=[
            {"type": "text", "text": INSTRUCTION},  # diagnosis.yaml에서 로드

        ]
    )
]

response = llm.invoke(messages)
```

4. **AI 응답 파싱**
```python
disease = re.search(r"<label>(.*?)</label>", response.content)
summary = re.search(r"<summary>(.*?)</summary>", response.content)

disease_name = disease.group(1)  # "여드름"
summary_text = summary.group(1)  # "이미지에서는 얼굴의 이마와 뺨 부위에..."
```

**AI 프롬프트 (`core/prompt/diagnosis.yaml`):**
```yaml
instruction: |

  - 다음 피부 질환 목록 중 가장 두드러진 주된 질환 1개를 <label>에 명시하라
  - 상세하고 포괄적인 설명을 제공하라 (최소 3-5문장, 150자 이상)

```

```python
# services/recommendation.py
def create_recommendations(db, analysis_id, member_id):
    # 1. 진단 결과 조회
    diagnosis = DiagnosisRepository.get_by_analysis_id(db, analysis_id)

    member = MemberRepository.get_by_id(db, member_id)
    
    # 3. Query 텍스트 생성
    query_text = f"{disease_name} 피부입니다. {summary}"
    
    # 4. Qdrant Vector 검색 (Top 10)
    search_results = VectorStoreService.search_similar(
        query_text=query_text,
        disease_name=disease_name,
        min_price=member.min_price,
        max_price=member.max_price,
        skin_type=member.skin_type,
        limit=10
    )
    
    # 5. LLM으로 최종 3개 선정 + 추천 이유 생성
    final_recommendations = _select_top3_with_llm(diagnosis, cosmetics, scores)
    
    # 6. MySQL에 저장
    return RecommendationRepository.create_bulk(db, recommendations_data)
```

**RAG 파이프라인 상세 흐름:**
1. 진단 결과(disease_name, summary) 조회
2. 회원 정보 조회 (skin_type, min_price, max_price)
3. Query 텍스트 생성 및 임베딩
4. Qdrant에서 유사 화장품 10개 검색 (Pre-filter: 가격, 질환, 피부타입)
5. MySQL에서 화장품 상세 정보 조회
6. LLM(GPT-4o-mini)이 최종 3개 선정 + 추천 이유 생성
7. MySQL recommendation 테이블에 저장

**자세한 내용은 [RAG 파이프라인 구축 가이드](#rag-파이프라인-구축-가이드) 참조**

#### 핵심 기술: DB VIEW 활용

**파일 경로:**
- `router/analysis.py` → `services/analysis.py` → `repository/analysis_view.py`

**처리 내용:**
```python
# services/analysis.py
view_results = AnalysisViewRepository.get_by_analysis_id(db, analysis_id)
```

**DB VIEW (`analysis_result_view`):**
```sql
CREATE VIEW analysis_result_view AS
SELECT 
    sa.analysis_id,
    sa.member_id,
    sa.created_at as analysis_created_at,
    f.file_id as skin_file_id,                -- 사용자 업로드 얼굴 사진
    d.disease_name,
    d.summary as diagnosis_summary,
    r.cosmetic_id,
    c.name as cosmetic_name,
    c.brand,
    c.price,
    c.buy_url,
    cf.file_id as cosmetic_file_id,           -- 화장품 제품 이미지
    r.reason,
    r.ranking
FROM skin_analysis sa
LEFT JOIN file f ON f.entity_type = 'skin_analysis' AND f.entity_id = sa.analysis_id
LEFT JOIN diagnosis d ON sa.analysis_id = d.analysis_id
LEFT JOIN recommendation r ON sa.analysis_id = r.analysis_id
LEFT JOIN cosmetic c ON r.cosmetic_id = c.cosmetic_id
LEFT JOIN file cf ON cf.entity_type = 'cosmetic' AND cf.entity_id = c.cosmetic_id
ORDER BY r.ranking;
```

### 6. 좋아요 기능

#### 특이 사항: 토글 방식

**작동 로직:**
```
1. INSERT 시도 (좋아요 추가)
   ↓
2. 성공? → 좋아요 완료
   실패 (UNIQUE 제약조건 위반)? → DELETE (좋아요 취소)
   ↓
3. 현재 좋아요 상태 + 총 개수 반환
```

**파일 경로:**
- `router/like.py` → `services/like.py` → `repository/like.py`

**DB 테이블 (`like`):**
```sql
CREATE TABLE like (
    like_id INT AUTO_INCREMENT PRIMARY KEY,
    member_id INT,
    cosmetic_id INT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    UNIQUE KEY unique_member_cosmetic (member_id, cosmetic_id)  -- 중복 방지
);
```

**Repository 구현:**
```python
# repository/like.py
def toggle_like(db: Session, member_id: int, cosmetic_id: int) -> dict:
    """좋아요 토글 (INSERT 실패 시 DELETE)"""
    
    try:
        # INSERT 시도
        like = Like(member_id=member_id, cosmetic_id=cosmetic_id)
        db.add(like)
        db.flush()
        return {"is_liked": True}
    
    except IntegrityError:
        # UNIQUE 제약조건 위반 → 이미 좋아요 존재
        db.rollback()
        
        # DELETE 실행
        db.query(Like).filter(
            Like.member_id == member_id,
            Like.cosmetic_id == cosmetic_id
        ).delete()
        db.flush()
        return {"is_liked": False}
```

## RAG 파이프라인 구축 가이드

### 개요

SkinMate의 화장품 추천 시스템은 **RAG (Retrieval-Augmented Generation)** 파이프라인을 활용하여 사용자의 피부 진단 결과에 맞는 최적의 화장품을 추천합니다.

### 기술 스택

- **Vector DB**: Qdrant Cloud
- **임베딩 모델**: multilingual-e5-large (1024-dim)
- **LLM**: OpenAI GPT-4o-mini
  - Vision 모델(진단): RunPod 호스팅 (이미지 처리용 GPU 필요)
  - 추천 LLM: OpenAI API (텍스트 생성, 토큰당 과금으로 비용 효율적)

### 아키텍처

```
사용자 진단 결과 (disease_name, summary)
   ↓
Query 텍스트 생성 및 임베딩
   ↓
Qdrant Vector 검색 (Pre-filter 적용)
   ├─ must: 가격 범위 (min_price ~ max_price)
   └─ should: 질환 매칭, 피부타입 매칭
   ↓
Top 10 화장품 검색
   ↓
MySQL에서 상세 정보 조회
   ↓
LLM에게 Top 10 전달
   ├─ 진단 정보
   ├─ 화장품 정보 (효능, 성분, 가격 등)
   └─ 선정 기준 (질환 관련성, 브랜드 다양성, 가격 밸런스)
   ↓
LLM이 최종 3개 선정 + 추천 이유 생성
   ↓
MySQL recommendation 테이블 저장
```

### 데이터 구조

#### Qdrant Collection 설계

**임베딩 텍스트 (메모리에서만 존재, 저장 X):**
```python
embedded_text = f"""
{description}
이 화장품의 주요 특징은 {short_description}입니다.
주요 효능은 {main_effect}이며, {care_symptom} 증상을 케어합니다.
핵심 성분은 {key_ingredient}입니다.
"""
```

**Qdrant 저장 내용:**
```python
{
    "id": cosmetic_id,
    "vector": [0.123, 0.456, ...],  # 1024-dim 벡터
    "payload": {
        "cosmetic_id": 1,           # MySQL 조회용
        "name": "시카페어 크림",     # 결과 표시용
        "brand": "라로슈포제",       # 결과 표시용
        "category": "크림",         # 결과 표시용
        "price": 28000,             # Pre-filter (must)
        "skin_type": "민감성",      # Pre-filter (should)
        "skin_disease": "여드름",   # Pre-filter (should)
    }
}
```

#### 검색 필터링 전략 (Hybrid)

```python
filter = {
    "must": [
        {"key": "price", "range": {"gte": min_price, "lte": max_price}}
    ],
    "should": [
        {"key": "skin_disease", "match": {"value": disease_name}},
        {"key": "skin_type", "match": {"value": skin_type}}
    ]
}
```

**Pre-filter 이유:**
- **must**: 가격 범위 밖 제품은 의미 없음 → 검색 전 제외
- **should**: 질환/피부타입 매칭 시 가점 → 유연한 검색

### 문제 해결

**Q: Vector 검색 결과가 없어요**
- 가격 범위가 너무 좁은지 확인 (`min_price`, `max_price`)
- Qdrant에 데이터가 적재되었는지 확인 (`test_qdrant_connection.py`)

**Q: LLM 응답이 이상해요**
- `recommendation.yaml` 프롬프트 확인
- LLM temperature 조정 (현재 0.7)
- Fallback 로직이 작동하는지 로그 확인

**Q: 임베딩이 너무 느려요**
- 배치 처리 사용 중인지 확인 (`embed_texts`)
- GPU 사용 가능 시 CUDA 활성화
